# US28 - Time Complexity Analysis Report
## Shortest Route Through Specified Stations Algorithm

### Overview
This document analyzes the worst-case time complexity of the algorithms implemented in US27 for finding the shortest route through specified stations. The analysis excludes graphic visualization procedures as specified in the acceptance criteria.

### Main Algorithm Structure

The US27 implementation uses the following key algorithms:
1. **Main Route Finding Algorithm** (`findShortestPathThroughStations`)
2. **Dijkstra's Shortest Path Algorithm** (`dijkstraShortestPath`)
3. **Supporting Data Loading Functions**

---

## Algorithm 1: Main Route Finding Algorithm

### Pseudocode
```
ALGORITHM findShortestPathThroughStations(edges, allStations, routeSequence)
INPUT: 
    - edges: List of railway connections
    - allStations: List of all available stations
    - routeSequence: Ordered list of stations to visit
OUTPUT: ShortestPathResult containing complete path and total distance

BEGIN
    completePath ← empty list
    totalDistance ← 0
    
    FOR i = 0 TO routeSequence.size() - 2 DO
        from ← routeSequence[i]
        to ← routeSequence[i + 1]
        
        segmentResult ← dijkstraShortestPath(edges, allStations, from, to)
        
        IF segmentResult is null OR segmentResult.path is empty THEN
            RETURN null
        END IF
        
        IF i = 0 THEN
            completePath.addAll(segmentResult.path)
        ELSE
            FOR j = 1 TO segmentResult.path.size() - 1 DO
                completePath.add(segmentResult.path[j])
            END FOR
        END IF
        
        totalDistance ← totalDistance + segmentResult.distance
    END FOR
    
    RETURN ShortestPathResult(completePath, totalDistance)
END
```

### Time Complexity Analysis

Let:
- **n** = number of stations (vertices)
- **m** = number of railway connections (edges)
- **k** = number of stations in routeSequence

**Primitive Operations:**
- Assignment (A)
- Increment (I)
- Comparison (C)
- Arithmetic Operation (Op)
- Return (R)

| Line | Algorithm findShortestPathThroughStations   | Operations Count      |
|------|---------------------------------------------|-----------------------|
| 1ª   | completePath ← empty list                   | 1A                    |
| 2ª   | totalDistance ← 0                           | 1A                    |
| 3ª   | FOR i = 0 TO routeSequence.size() - 2       | 1A + (k-1)C + (k-1)I  |
| 4ª   | from ← routeSequence[i]                     | (k-1)A                |
| 5ª   | to ← routeSequence[i + 1]                   | (k-1)A + (k-1)Op      |
| 6ª   | segmentResult ← dijkstraShortestPath(...)   | (k-1) × O(n² + m)     |
| 7ª   | IF segmentResult is null OR ...             | (k-1)C                |
| 8ª   | RETURN null                                 | 1R (worst case)       |
| 9ª   | IF i = 0                                    | (k-1)C                |
| 10ª  | completePath.addAll(segmentResult.path)     | 1 × O(n)              |
| 11ª  | FOR j = 1 TO segmentResult.path.size()      | (k-2) × O(n)          |

| 13ª  | totalDistance ← totalDistance + ...         | (k-1)A + (k-1)Op      |
| 14ª  | RETURN ShortestPathResult(...)              | 1R                    |

**Total Operations:** O(k × (n² + m)) + O(k × n) = **O(k × (n² + m))**

**Time Complexity Estimate:** **O(k × (n² + m))**

## Algorithm 2: Dijkstra's Shortest Path Algorithm

### Pseudocode
```
ALGORITHM dijkstraShortestPath(edges, allStations, source, destination)
INPUT:
    - edges: List of railway connections
    - allStations: List of all stations
    - source: Starting station
    - destination: Target station
OUTPUT: DijkstraResult containing path and distance

BEGIN
    // Graph construction
    graph ← empty adjacency list map
    FOR each station in allStations DO
        graph[station] ← empty list
    END FOR
    
    FOR each edge in edges DO
        from ← edge[0]
        to ← edge[1]
        weight ← parseInt(edge[3])
        
        graph[from].add(Edge(to, weight))
        graph[to].add(Edge(from, weight))
    END FOR
    
    // Initialize Dijkstra data structures
    distances ← map with all stations set to INFINITY
    previous ← empty map
    unvisited ← set containing all stations
    distances[source] ← 0
    
    // Main Dijkstra loop
    WHILE unvisited is not empty DO
        current ← null
        minDistance ← INFINITY
        
        // Find minimum distance unvisited node
        FOR each station in unvisited DO
            IF distances[station] < minDistance THEN
                minDistance ← distances[station]
                current ← station
            END IF
        END FOR
        
        IF current is null OR distances[current] = INFINITY THEN
            BREAK
        END IF
        
        unvisited.remove(current)
        
        IF current equals destination THEN
            BREAK
        END IF
        
        // Relax neighbors
        FOR each edge from current DO
            IF edge.to is in unvisited THEN
                newDistance ← distances[current] + edge.weight
                IF newDistance < distances[edge.to] THEN
                    distances[edge.to] ← newDistance
                    previous[edge.to] ← current
                END IF
            END IF
        END FOR
    END WHILE
    
    // Reconstruct path
    path ← empty list
    current ← destination
    
    IF destination not in previous AND source ≠ destination THEN
        RETURN null
    END IF
    
    WHILE current is not null DO
        path.addFirst(current)
        current ← previous[current]
    END WHILE
    
    RETURN DijkstraResult(path, distances[destination])
END
```

### Time Complexity Analysis

Let:
- **n** = number of stations (vertices)
- **m** = number of railway connections (edges)

**Primitive Operations:**
- Assignment (A)
- Increment (I)
- Comparison (C)
- Arithmetic Operation (Op)
- Return (R)

| Line | Algorithm dijkstraShortestPath   | Operations Count |
|------|----------------------------------|------------------|
| 1ª   | graph ← empty adjacency list map | 1A               |
| 2ª   | FOR each station in allStations  | nA               |
| 3ª   | FOR each edge in edges           | mA + 2mOp        |
| 4ª   | distances ← map initialization   | nA               |
| 5ª   | unvisited ← set initialization   | nA               |
| 6ª   | distances[source] ← 0            | 1A               |
| 7ª   | WHILE unvisited is not empty     | nC               |
| 8ª   | Find minimum distance node       | n²C              |
| 9ª   | unvisited.remove(current)        | nOp              |
| 10ª  | IF current equals destination    | nC               |
| 11ª  | FOR each edge from current       | mC + mA          |
| 12ª  | Distance relaxation operations   | mC + mA + mOp    |
| 13ª  | Path reconstruction              | nA               |
| 14ª  | RETURN DijkstraResult            | 1R               |

**Total Operations:** 2n²C + 3nA + 4mA + 3mOp + 2mC + nOp + 1R = **2n² + 6n + 9m + 1**

**Time Complexity Estimate:** **O(n² + m)**

## Overall System Complexity Analysis

### Complete US27 Algorithm Complexity

**Input Parameters:**
- **n** = total number of stations
- **m** = total number of railway connections
- **k** = number of stations in the route sequence

**Component Complexities:**
1. **Data Loading:** O(n + m)
2. **Route Finding:** O(k × (n² + m))
3. **User Input Processing:** O(k) - not counted as primitive operations

**Total Worst-Case Time Complexity: O(k × (n² + m))**

### Space Complexity Analysis

**Space Requirements:**
- **Graph representation:** O(n + m) for adjacency lists
- **Dijkstra's data structures:** O(n) for distances, previous, and unvisited sets
- **Path storage:** O(k × n) in worst case for storing all segment paths
- **Total Space Complexity: O(k × n + m)**

### Complexity Justification

The **O(k × (n² + m))** complexity arises because:

1. **Sequential Path Finding:** The algorithm finds k-1 the shortest paths sequentially
2. **Dijkstra Implementation:** Uses a naive implementation without priority queue, resulting in O(n²) vertex selection
3. **No Path Reuse:** Each segment is computed independently without optimization

### Potential Optimizations

**Note:** These are theoretical improvements not implemented in the current solution:

1. **Priority Queue Dijkstra:** Could reduce single-path complexity to O((n + m) log n)
2. **All-Pairs Shortest Path:** Precompute with Floyd-Warshall O(n³) for multiple queries
3. **Bidirectional Search:** Could reduce average-case complexity

### Conclusion

The implemented algorithm has a worst-case time complexity of **O(k × (n² + m))**, which is acceptable for moderate-sized railway networks. The complexity grows linearly with the number of intermediate stations and quadratically with the network size, making it suitable for practical railway routing applications with reasonable performance characteristics.

The space complexity of **O(k × n + m)** is also reasonable, with the main space usage coming from graph representation and path storage.
